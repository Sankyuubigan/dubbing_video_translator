# 16.09.26 TTS: клики, обрезание слогов, время генерации

## Доказанные факты (код/логи/прогоны)
- Клики в **середине** чанка не могут быть от склейки: `place_samples` (tts/mod.rs:427) меняет только границы (fade-in/fade-out).
- Клик есть и в `raw` (=байт-в-байт ответ движка) → источник = RAS-семплер cosyvoice3, seed-зависимый артефакт.
- Обрезание: `RetryTracker` принимает короткую генерацию при двух похожих seed (лог: чанк 7 → 1.48с при ожид≈2.50с).
- **Корень бага обрезания (17.09, ДОКАЗАНО тестом)**: `RetryTracker` не знал «ожидаемую» длительность — правило `near_best_count >= 2` принимало консенсус ДВУХ одинаково КОРОТКИХ «близнецов» за полное прочтение. Ч.7: обе попытки 1.48с при ожидании 2.50с (11 гласных ÷ 4.4) → 0.59×expected → стоп и выдача обрезанного хвоста. Фикс: `expected` передаётся в трекер, стоп только при `best >= TTS_FULL_FLOOR×expected` (0.62; обоснование: самое быстрое реальное чтение = 4.4/6.9 ≈ 0.638×expected, обрезанный ч.7 = 0.592).
- `amix` (output/mod.rs:149) делает renormalize по 1/N активных входов — скачок уровня при выпадении входа (чинить в Фазе 2).
- FFmpeg у нас: gyan.dev full build 2024-04-10, PATH; `--enable-librubberband`.
- **Инфраструктура теста (17.09)**: юнит-тест-харнесс на этой машине НЕ запускается (STATUS_ENTRYPOINT_NOT_FOUND — CUDA DLL при загрузке; это же сообщение всегда было в `test.bat` → «compilation succeeded though»). Проверка логики RetryTracker выполняется через автономный бинарь `test-retry-tracker` (`build_test_retry.bat`), который РАБОТАЕТ (RED→GREEN, прогоны см. ниже).

## Исследование кликов (17.09, задокументировано, НЕ внедрялось)
- Формы: ч.3 клик≈5.0785с — HF-звон (серия альтернаций ~1-2 сэмпла, max-delta 11952) на ТИХОМ фоне (RMS ctx 0.05-0.08); ч.27 клик≈2.3016с — ступенчатый подъём за 5-8 сэмплов (max-delta 8734) в ГРОМКОМ контексте (RMS 0.18-0.25).
- Речь: ч.5 атака «S» 1.5564с (delta 9036, RMS большой) и ч.14 осцилляция 0.56с — по форме почти неотличимы от кликов; max-delta речи (ch05 0.276, ch14 0.48 FS) > кликов (ch03 0.365, ch27 0.267).
- Кривизна (2-я разность) и плоскотность спектра не разделяют (ch05 3830 ≈ ch27 3500).
- Прототипы AR-2-починки давали 0.365→0.246 (не <0.20), медианный аутлаер портил контрольные файлы. Амплитудно-детектный фикс невозможен → клики отложены (см. выше).

## Текущий подход
- Retry отвечает ТОЛЬКО за полноту: консенсус 2 попыток в пределах 3% И максимум ≥ 0.62×expected (TTS_FULL_FLOOR) — фикс обрезаний (см. «Фикс обрезания»). **Гейт по бэкенду**: `attempt_count = if tts_backend == "cosyvoice3-tts" { TTS_MAX_ATTEMPTS } else { 1 }` — для RL-модели (cosyvoice3-tts-rl) всегда 1 попытка, костыль выключен.
- Щелчки: **пост-обработка** `declick_spikes` (tts/mod.rs): сглаживание 1-сэмпловых выбросов (V-пик: оба перепада >0.22 → замена средним соседей; обрыв >0.45 → гашение) в финальных сэмплах каждого чанка перед укладкой. O(n), без перегенераций.

## ПЕРЕХОД НА RL (17.09, вечер) — костыли отключены гейтом по backend
- Перешли на **cosyvoice3-tts-rl** (RL-постобучение): стабильная, без обрезаний и кликов. Прогон 38 чанков: TTS 115.3s (base 202.7s), TOTAL 170.0s, 1 попытка на чанк, ч.7 полный (38 токенов против 13 у обрезанного base) — прослушано пользователем, обрезаний нет.
- base удалена с диска и из обоих speech_models.json (проектный + плагин).
- **Деклик выключен тем же гейтом**: `if tts_backend == "cosyvoice3-tts" { declick_spikes(...) }` (tts/mod.rs). Клики были артефактом base-модели (фикстуры ч.3/ч.27 — test/tts_declick_fixtures — сняты с base-прогона 17.09 01:58; RL-файл создан 23:34). Для RL вызов пропускается (zero overhead). Функция и тесты (build_test_declick.bat) оставлены как документация костыля: если base вернётся — включится автоматически.
