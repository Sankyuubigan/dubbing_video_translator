# Правила проекта DubVidTra2

## Стек
- **Бэкенд:** Rust + Tauri 2.0
- **Фронтенд:** React (Tauri default)
- **Нейронки:** sherpa-onnx (ONNX), llama-cpp-2 (GGUF)
- **Медиа:** FFmpeg (внешняя зависимость, только для audio_extractor и output/mux)

## Архитектурные правила
1. Модули не импортят друг друга — только через comm.rs.
2. Каждый модуль — отдельная папка в src/.
3. Все модели выгружаются после использования (drop(model) перед загрузкой следующей).
4. VAD (Silero) использует встроенный VoiceActivityDetector из sherpa-onnx.

## Соглашения по коду
- Комментарии на русском (личный проект).
- Публичные функции модуля — только те, что указаны в архитектуре.
- Ошибки пробрасывать через anyhow.
- Максимальная длительность чанка: 6 секунд (константа MAX_CHUNK_LEN в stt/mod.rs, слияние соседних сегментов).
- **Максимальная длина текста субтитра: 65 символов** (константа MAX_TEXT_CHARS в stt/mod.rs). Длинные чанки автоматически разбиваются по границам предложений, время распределяется пропорционально.
- LLM перевод: тегированная построчная генерация (формат [N] текст), парсинг через regex.

## Pipeline — порядок и проверки

### Порядок стадий (НЕ МЕНЯТЬ!)
1. audio_extractor — извлечение WAV из видео
2. vad — детекция речевых сегментов (Silero VAD)
3. diarization — идентификация спикеров (PyAnnote + TitaNet) — **ДО STT**
4. stt — распознавание речи с нарезкой по границам спикеров
5. translation — перевод через LLM
6. output — вшивание субтитров в видео

### Проверка пайплайна в конце каждой задачи
После любых изменений в коде пайплайна, stt, diarization или vad — **обязательно**:
1. `cargo build` — убедиться, что компилируется
2. Прогнать на `test/for_test.mp4` (или аналогичном тестовом видео)
3. **Проверить субтитры по контексту:**
   - Открыть выходной файл `test/for_test_subbed.mp4`
   - Визуально проверить, что спикеры назначены правильно
   - Если есть диалог: проверить, что реплики разных людей не склеены под одним спикером
   - Если есть длинный монолог: убедиться, что он не разбит на разных спикеров
4. **Проверить длину субтитров:**
   - Ни один субтитр не должен содержать больше 65 символов текста
   - Если видишь на экране больше 2 строк текста — это баг
   - Если весь экран забит текстом — значит `split_long_chunks` не сработал
5. Проверить логи — нет ли предупреждений о перекрытии сегментов, пустых распознаваниях

### Проверка корректности спикеров
При проверке субтитров обращай внимание:
- **По контексту:** Читай текст субтитра. Если написано `[Speaker_1] How tall are you? I'm five seven` — это баг (один спрашивает, другой отвечает, но оба под одним спикером)
- **Временные метки:** Если у двух последовательных субтитров одного спикера разрыв менее 0.5с — проверь, не должны ли они быть слиты
- **Пустые спикеры:** `[Speaker]` (без номера) — признак того, что не удалось определить спикера для этого фрагмента. Должно быть минимум таких случаев
- **Количество спикеров:** Если в диалоге участвует N человек, в субтитрах должно быть ровно N уникальных Speaker_N

## STT (Speech-to-Text)
- Модель: Qwen3-ASR через sherpa-onnx (ONNX)
- Word-level тайминги: НЕ поддерживаются текущей моделью (word_timestamps = None)
- Для word-level таймингов требуется альтернативный бэкенд (whisper-rs / Whisper.cpp)
- Макс. длина сегмента на распознавание: 6 секунд
- **Макс. длина текста субтитра: 65 символов** (константа MAX_TEXT_CHARS). Длинные чанки автоматически разбиваются на несколько субтитров с пропорциональным распределением времени.

### Разбивка длинных субтитров (split_long_chunks)
После распознавания текста все чанки длиннее 65 символов разбиваются:
1. **По границам предложений** (`.`, `?`, `!` — с учётом сокращений Mr., Dr., etc.)
2. Если предложение длиннее 65 символов — **по словам** на последнем пробеле
3. Время распределяется **пропорционально длине текста** каждой части

Это гарантирует, что на экране никогда не будет больше ~2 строк текста на субтитр.

### Спикер-аварное распознавание
- STT получает уже готовые SpeakerSegment из модуля diarization
- Функция `split_vad_by_speakers()` разрезает VAD-сегменты по границам спикеров
- Если сегменты спикеров перекрываются — более поздний обрезается до конца более раннего (с лог-предупреждением)
- После нарезки соседние подсегменты одного спикера сливаются (gap ≤ 0.5с, сумма ≤ 6с)

## VAD (Voice Activity Detection)
- Модель: Silero VAD v5 (silero_vad.onnx)
- Загрузка: автоматическое скачивание в models/vad/ при первом запуске
- URL: https://github.com/snakers4/silero-vad/raw/master/src/silero_vad.onnx
- Библиотека: встроенный VoiceActivityDetector из sherpa-onnx (не ort)
- Параметры: threshold=0.5, window_size=1536, padding=0.15с

## Diarization (Speaker Identification)
- Модели: PyAnnote segmentation + NeMo TitaNet embedding (ONNX)
- **Параметры по умолчанию:**
  - `threshold: 0.95` — порог кластеризации (выше = меньше спикеров, стабильнее)
  - `min_duration_on: 0.5` — мин. длина сегмента
  - `min_duration_off: 0.3` — мин. пауза для смены спикера (было 1.0 — исправлено)
- Пост-обработка: удаление коротких сегментов, слияние соседних одного спикера, переприсвоение минорных (<5%)
- **Гарантия минимум 2 спикера:** если модель детектировала 2+ разных спикеров, после пост-обработки останется минимум 2 (защита от схлопывания)

## Translation (LLM)
- Формат промпта: построчные теги [N] вместо JSON
- Парсер: regex `\[(\d+)\]\s*(.*)`
- Лимит генерации: max_new = min(input_tokens * 2, 4096)
- Fallback: при пропуске индекса — оригинальный текст

## GUI (Tauri)
- Драг-н-дроп видео в основное окно.
- Кнопка "Выбрать GGUF-модель" — открывает файловый диалог для .gguf.
- Поле "Выходной формат" — по умолчанию совпадает с входным.
- Прогресс-бар: отображает стадию (VAD, STT, перевод...) и проценты.
- По окончании — кнопка "Открыть папку с результатом".

## Тестирование
- **Unit-тесты:** каждый модуль тестируется изолированно.

- cargo test — запуск всех тестов.
- cargo test -- --nocapture — с выводом логов.

## Первый запуск
1. Установить FFmpeg (должен быть в PATH).
2. Скачать модели (автоматически при запуске):
   - Silero VAD v5 → models/vad/silero_vad.onnx
   - PyAnnote segmentation → models/diarization/sherpa-onnx-pyannote-segmentation-3-0/
   - NeMo TitaNet embedding → models/diarization/nemo_en_titanet_small.onnx
3. Вручную указать пути:
   - Qwen3-ASR (sherpa-onnx) — директория с encoder/decoder/tokenizer
   - Qwen-2.5-7B GGUF — файл .gguf для перевода
4. Кинуть видео → нажать "Обработать".
